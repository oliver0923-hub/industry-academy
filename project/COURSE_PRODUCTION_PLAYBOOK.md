# Industry Academy｜課程製作總流程（Course Production Playbook）

**版本**：v1.0｜2026-11-09  
**範圍**：00–49 正式課程及非編號跨產業專題；ChatGPT、Codex、研究資料與網站協作的完整操作流程。  
**維護方式**：本檔為「如何製作與交付」的操作規範；不取代 [正式教學與編輯規範](../EDITORIAL_TEACHING_STANDARDS.md) 的 20 項內容決策，也不更動 Master v2.0 固定課號。重大流程更動應更新本檔版本及 [第 02 課實作紀錄](LESSON_02_OPERATION_LOG.md)。

## 0｜一句話原則與責任分工

**使用者提出方向 → ChatGPT 整理課次、問題與證據需求 → 必要時 Codex 搜尋／下載／核實來源 → ChatGPT 讀原件、調和證據、撰寫並修訂教材 → 整合至獨立課程閱讀頁 → 實際網站驗收 → 紀錄版本與未解缺口。**

| 階段 | 主責 | 核心交付 | 不能跳過的判斷 |
|---|---|---|---|
| A. 命題與範圍 | 使用者提出；ChatGPT 整理 | 課次簡報、讀者問題、既有資產盤點 | 是否已有可用來源？是否屬固定 00–49 課次？ |
| B. 研究規格 | ChatGPT | 可執行的 Codex 任務（不是空泛「多找資料」） | 缺少哪些正式原始數值、歷史與案例？ |
| C. 原始資料 | Codex／合法資料庫工具 | Evidence Pack、原始件私存、逐項核對表、缺口報告 | 書目、下載、全文核讀與主張核驗分開 |
| D. 語料交接 | ChatGPT | 重新解壓、逐表抽查、來源／口徑衝突清單、寫作可用性判定 | ZIP 或 GitHub 文件存在 ≠ 真正審讀 |
| E. 教材寫作 | ChatGPT | 完整繁中敘事稿、主張—來源連結、圖表稿、來源表 | 概念先白話、數據不混算、避免只講科技大廠 |
| F. 教學編修 | ChatGPT，另安排獨立審查 | 易讀稿、長文節奏、歷史與台灣產業多元化 | 初學者能不能在第一次閱讀理解？ |
| G. 網站實作 | ChatGPT／被授權的 Codex 程式工作 | `docs/` 正確課程檔與共用閱讀器設定 | 「目錄→下一個網頁→完整單篇課文」，不嵌進首頁 |
| H. 測試、發布與追蹤 | ChatGPT／網站維護者 | 靜態測試、實際部署檢查、四關編輯審查、變更日誌 | GitHub commit ≠ GitHub Pages 最新版已可瀏覽 |

**預設路線**：研究資料不足就先做 B–D；已有足夠、已核對的證據就直接做 E–H，**不要為了流程而重複啟動 Codex**。每個階段允許往回修補，不能把缺漏默默補成虛構事實。

## 1｜固定規範、分支與資料位置：開始任何課必先核對

1. **課綱**：Master Instructions v2.0，編號 00–49 和產業邊界維持原樣；學院目錄顯示在 `docs/app.js` 的 `TITLES`，課文大標題可較易讀，但不能未授權變更正式課名。
2. **教學與出版決策**：[根目錄 EDITORIAL_TEACHING_STANDARDS.md](../EDITORIAL_TEACHING_STANDARDS.md) 優先於 Master v2.0 衝突部分：自然敘事、非固定章節、10k–15k **正文中文字**僅作彈性基準、3–5 道理解問題和適切情境、出版前四關。
3. **給執行代理的規則**：[根目錄 AGENTS.md](../AGENTS.md)；本 SOP 則規定跨工具交接。
4. **正式網站分支**：`main`，GitHub Pages 從 `main:/docs` 發布。網站目錄是 `docs/index.html#catalog`。
5. **研究分支**：`codex/research-source-foundation` 已有較完整的 `research/` 來源庫、查核程式與歷史紀錄；它與 `main` 不是同步鏡像，**不能直接把舊 research 分支整枝合併或覆寫 main 的 docs**。
6. **來源分區**：公開 Git 存作者整理的研究筆記、必要數值、來源 locator、校驗碼及可公開重繪圖表；原始論文全文、授權 PDF、大量下載檔、機密或受限文件僅存被 Git 忽略的 `private_sources/`，不放 `docs/`。
7. **分支作法**：研究工作從最新研究基底開 `codex/lesson-NN-evidence-YYYYMMDD`；網站工作依最新 `main` 開 `codex/lesson-NN-site-YYYYMMDD` 或依當輪明確授權直接更新 main。切換前檢查 branch、SHA、dirty tree，保留非本次工作異動。完成研究後採證據包／受控 PR／挑選提交方式移交；不可假設研究與網站分支的歷史相容。
8. **台灣官方分類**：以撰寫當下有效官方版次與生效日查核，2026-01 起第 12 次修正已生效；舊第 11 次修正只作歷史對照。教學主題／公司／場所／HS 商品碼／NAICS／SIC／TWSE 不能強制一對一。

## 2｜A 階段：使用者提出一堂課，ChatGPT 應先做什麼

**輸入可以非常簡短**：「開始第 NN 課」「我想用 XX 產業作案例」「本堂希望加入某家公司」。已知課次、語氣與網站規格不可反覆要求使用者重述。

ChatGPT 必須先：

1. 對照正式 00–49 課名及既有文章，辨別這是**新課、修訂、增補案例**還是**獨立跨產業專題**。
2. 讀 `AGENTS.md`、編輯規範、現有 `README.md`、相關研究索引、既有來源包及網站檔；**不要只看網站佔位頁**。
3. 提出可教學的開場主題、讀者要回答的 3–5 個核心問題、產業／地理／期間邊界、全球及台灣最需要交代的活動與企業。
4. 逐項盤點：官方分類、全球實際量值、台灣實際量值、產業史、製程／服務交付、成本價值鏈、期刊機制、企業原始文件、圖片／圖表授權、最新政策與變化。
5. 用「已核對／有來源待核對／僅找到入口／缺失／不可取得」標示，決定 **GO（證據足夠可寫）** 或 **FETCH（需 Codex 補證）**，並指出真正影響課文的 3–6 個缺口；不要用資料筆數代替充分性。

**A 階段交付**：短版 `Lesson Brief`（主題、切角、讀者、主案例、台灣對照、需用資料、開場、關鍵缺口、GO/FETCH）。若 FETCH，緊接交付完整 Codex 執行指令。

## 3｜B 階段：ChatGPT 產出 Codex 的「可執行資料抓取任務」

Codex 任務應包含下列所有資訊，採 [可複製的交接模板](LESSON_HANDOFF_TEMPLATE.md)：

- 完整 `owner/repo`、**正確研究分支**與工作分支、不能修改 `docs/`／`main` 的工作邊界；先讀現有 `research/` 與既有證據，查重、續跑而非重抓。
- 本堂 3–6 個**具體的必補問題**與每項優先來源；每個來源列官方入口、所需表格／章節或 DOI、期間、地理、指標、判定資料足夠的標準。先查現有文件與程式，不能亂猜 CLI 參數。
- 分級：P0 必需官方量值／官方史料／原始制度，P1 同行評審期刊原文與原始公司案例，P2 原創圖表規格與可選內容；依主題調整，不強制每課相同來源。
- 統計欄位：`issuer,title,url,version,publication_date,data_period,indicator,definition,unit,currency,nominal_real,geography,industry_code,observation,formula,locator,retrieved_at,status`。
- 每篇文獻欄位：DOI／正式期刊版次、全文狀態、理論或模型、樣本與期間（若適用）、方法、能支持的**具體主張**、頁碼／段落定位、反例與適用邊界；不得把摘要視為全文。
- 公司案例欄位：文件年度／會計年度、集團與個體、地區、決策及時間點、財務或營運結果、企業宣稱與獨立觀察、不能推論的部分。
- 成功／失敗／受限的日誌、SHA、合法授權、原始檔私存及可重製資料、逐項 claim-to-source 表格；不能只交一份「來源清單」。
- **停止條件與驗收**：最重要數值與案例實際核對、缺口坦白列出；自動驗證通過仍不能自稱正式教材完成。缺件記阻礙及替代來源，不無限抓取、不繞過帳密或 robots。

研究分支已有 `research/scripts/full_acquisition.py` 等程序；執行前使用 `--help` 確認，再依實際參數做 `--lessons NN --dry-run --resume --skip-verified`。真實取得過程遵守來源授權、API 限額及原文引用限制。

## 4｜C 階段：Codex 如何交付，讓下一次對話不必重來

Codex 將成果交付在研究分支 `research/evidence/lesson-NN-YYYY-MM-DD/`，或明確附上等價 ZIP 與其 manifest。建議至少包含：

- `README.md`：本輪範圍、運行日期、base commit、所讀原始版本、完成度與限制。
- `source_inventory.csv`：每個原始來源身份、版次、URL、本機存取狀態、SHA256、授權／限制。
- `claims_evidence.csv`：主張、類型（事實／測量／相關／因果／理論／企業說法／預測／推論）、來源 ID、原文 locator、核對程度、邊界。
- `indicator_series.csv`：**可追蹤原始觀察列**，非只有網站首頁；必要時加計算程式／資料字典。
- `literature_reviews.md`／`.csv`：同行評審文獻與全文／摘要狀態、研究設計和限制。
- `company_cases.md`：國際與台灣代表企業的可核實故事、決策、時間線及限制。
- `history_timeline.csv`、`figure_spec.md`：史料、圖表數據／示意別、授權、再現方式。
- `gaps.csv`、`quality_review.md`：缺失、衝突、未解問題及哪些會阻擋發布。
- 有價值的初步敘事／章節藍圖，但**不能以空泛大綱取代資料**。

研究過程只由 Codex 報告實際執行的腳本與測試，包括 `python research/scripts/validate_full_acquisition.py`、`validate_deep_evidence.py`、`validate.py`（檔案存在且適用時）及 `git diff --check`。交接要寫清楚 branch、commit、取得／拒絕筆數、未完成項目及原檔是否真的可在下個環境讀到。

## 5｜D 階段：ChatGPT 收到研究包後必須自己重查

**不要直接相信「成功下載 100 個」「驗證全部 PASS」或摘要敘事。**

1. 確認拿到的 ZIP、GitHub 分支與 commit，安全解壓與盤點檔名、數量、格式、CRC／SHA；若只有 manifest 而沒有原文，列為「未在本環境取得」。
2. 開啟實際 CSV/XLSX/PDF/HTML／政府表格，抽查關鍵列與書目；PDF 中的圖表、表格應實際檢視。核對年份、單位、統計對象與版本。
3. 建立「想放入文章的主張 → 最可信的原始文件 → 精確定位 → 限制」對照，區分有來源與真的被來源支持。
4. 對矛盾資料先比較統計範圍、版本、貨幣、名目／實質、個體／合併、流量／存量；**不要為了完整圖表而強行拼接**。
5. 分出：正文可用、僅可概念示意、需用保留語、不可用；若必要的核心證據尚缺，回到 B 階段產出一次**針對缺口**的 Codex 補抓指令。
6. 發出 **Writing Readiness**：能寫什麼、哪些數字不可用、預計圖表和案例、剩餘審查缺口；未齊全時可先寫證據支持的段落，不得捏造。

這個階段是 ChatGPT 自己的核讀與判斷，不把 Codex 的結果當成可直接貼上的正式課文。

## 6｜E、F 階段：ChatGPT 撰寫及易讀化（延用第 02 課經驗）

- **先故事，再概念**。讀者看見什麼產品／服務？誰提供？流程怎麼運作？企業為何這樣安排？最後才帶出正式術語與期刊研究。避免一開始就堆「複雜度／可編碼性／治理型態／內生性」。
- 文章是**一篇能持續閱讀的繁體中文教科書**；各段要有因果和轉折。將一段同時包含五個定義、三筆統計、兩份限制的文字拆開，先用情境再說精確口徑。
- 歷史回答**為什麼改變**，不是只排事件日期；台灣案例跨不同型態企業與產業，不以半導體代表整個台灣。可主例帶讀，其他企業作有用對照，避免名詞清單。
- 正文完整性檢查：定義與邊界、歷史、全球活動、核心技術／交付、價值鏈與成本、台灣角色、競爭機制、企業故事、變化與風險、跨課連結。
- 嚴格區分商品貿易額、企業營收、工廠產量、附加價值、FDI 流量／存量、核准投資與資本支出；不同口徑不能以同一個指標作排名或加總。
- 學術期刊直接支持該段的機制，**不用每段塞作者**；文末附作者、年、期刊、DOI。事實性資料記原始發布年及觀測年。假設數值標示「教學示意」。
- 正文篇幅通常 10k–15k 中文字，**只統計正文**（排除參考文獻、程式碼、大型數據表），篇幅為指標不是免責的內容充分性。
- 課末通常 3–5 題理解問題、1 個情境、術語表、完整來源與延伸課程；不強制三回合模擬、選擇題或固定 11 章。
- 撰寫完成還要做**第三關易讀性修稿**：逐段問「零基礎讀者是否知道這句話在說什麼」「主詞與動作是否清楚」「能否換成生活例子」「來源註記是否壓過故事」。保留重要限制，但放在適當位置，不為白話化犧牲精確度。
- **原則上保存兩層內容**：`editorial/lessons/lesson-NN/draft.md`（不依賴網頁才能讀的可版本化母稿）；`docs/lesson-NN-reading.html`（網站載入的教材頁內容）。以前存在的獨立教材 HTML 可以繼續作來源，不必為了整齊一次重建舊課。
- 公開教材**不得提到** Codex、ChatGPT、內部 ZIP／資料包、下載／生成工序、私人研究計畫；內部工作記錄可如實寫。

## 7｜G 階段：固定網站閱讀動線，未授權不得回退

**2026-11-09 起採用：**

```text
docs/index.html#catalog                 50 課搜尋／選課目錄
     │ 點選任何課程
     ▼
docs/lesson.html?lesson=NN               下一個獨立閱讀頁（非首頁側欄）
     │
     ├─ 已有可閱讀教材：長文、章節目錄、進度條、字級、放大、前後堂導航
     └─ 尚無完整教材：清楚顯示「編寫中」，不偽裝已發布
```

- 讀者從總目錄進到**另一個 HTML 頁面**；課文內是一篇連續長文，**不拆成每節一頁**。保留原始來源、圖表、可開啟目錄、進度及上次位置。
- 當前共用入口：`docs/lesson.html`。閱讀載入與已完成清單：`docs/lesson-reader.js` 的 `sourceFiles`，以及 `docs/lesson.html` 的可讀課次分支（目前 `id > 2` 顯示編寫中）。**未來新增第 NN 堂，兩處都須更新，且需統一候選／正式狀態**。正式標示還需看四關審查，不以「檔案可讀」等同正式發布。
- 目錄的課名與連結：`docs/app.js` 的 `TITLES` 與 `courseHref()`；50 課穩定，**不要為了讓全文展示而把內容直接插進 `index.html`**。
- 現有 `docs/lesson-00-reading-v2.html`、`lesson-01.html`、`lesson-02-reading.html` 是**教材內容來源檔**，讀者應從 `lesson.html?lesson=NN` 進入。允許這些檔案保留，但不把它們當成課程目錄的主要目的地。
- 舊網址 `index.html#lesson/0`、`#lesson/1`、`#lesson/2` 已有轉向機制；後續若新增課程亦需一併考慮既有書籤與深連結。
- 不任意破壞進度資料；`localStorage` 只在本瀏覽器有效，點開網頁不代表完課。閱讀器載入失敗要顯示錯誤與可重試，不留空白。
- 網頁僅承載公開可散布的原創文字、圖表及適當引述，不把研究原始受限檔案放進 `docs/`。

**網站更新步驟**：（1）確認最新版 main 與差異；（2）新增／更新教材 HTML；（3）更新兩處可讀課次及課程狀態；（4）必要時更新 CSS/JS 並進行 cache bust；（5）檢查 50 堂目錄與相鄰課連結、章節 anchor、來源連結及圖表；（6）實際瀏覽器桌機／手機驗收；（7）核對 GitHub Pages 真實線上部署。未驗證部署則明說「已提交 GitHub，Pages 尚待驗證」。

## 8｜H 階段：四關審查和可用狀態

來源狀態與課文狀態**獨立管理**：

- 研究：`identified → acquired → source_reviewed → claim_verified`（可逐主張不同進度，不能整堂一筆概括）。
- 教材：`not_started → research_in_progress → draft → editorial_review → publication_ready → published`。
- 網站：`no_page / staging / committed_to_main / pages_deployed_verified`。
- 任何一個 `source_reviewed`、`syntax_pass`、`commit_done` **不表示** `published`。

出版級四關：① 逐項**事實與來源**（日期、數值、分類、財報、原始文件）；② **理論與推論**（事實／相關／因果／推測，反例與邊界）；③ **一般讀者教學與語言**（故事、歷史、數字解說、無術語障礙）；④ **獨立第二輪審讀與修訂**（不同視角檢查，實際執行才填通過）。

網站技術檢查分列：JS 語法與引用、50 堂目錄連結、每堂已授權的來源頁、錨點及圖表、手機水平溢出、鍵盤／可讀性、上一堂／下一堂、存取本機進度、外部參考資料實際可達、GitHub Pages **線上**實測。若未跑 Browser/Playwright 就不能勾「通過」。

## 9｜收尾交接：每堂完成後必留的紀錄

在 `project/LESSON_NN_OPERATION_LOG.md`（或該課 `editorial/lessons/lesson-NN/CHANGELOG.md`）記錄：

1. 課號、原始需求、讀者／目標、提案日期；有沒有後續使用者修正。
2. 研究分支、工作分支與 commit；既有來源、Codex 新抓來源、ZIP 內容核對／缺失。
3. 哪些來源可實際支持文章的哪個主張；範圍、期間、單位、頁碼；未解爭議與不可使用的數字。
4. 母稿／網站稿版本、主要案例、修稿原因及多元台灣產業對照。
5. 內容四關各自狀態、技術 QA 實測、公開網站版本是否驗證、尚待下一步。
6. 下次續作所需的**單一句話起點**（不用重新討論設定）。

**完成報告**以事實交付為主：實際修改哪些檔案、哪個分支／commit、哪些檢查通過、哪裡仍待處理；提供課文與目錄實際入口，不把 Codex 抓完來源或 GitHub 上傳成功當成正式出版。
